# Fellow 學伴｜從一個學習問題，走向完整的支持系統

**學生敢問、家庭找得到協助、教師看見需要，公共部門理解需求。**

小晴是一位來自農業家庭的高中生。晚上複習化學時，她分不清「氫鍵」與「共價鍵」；家裡最近也為收入不穩定而煩惱。對她而言，學習與生活不是分開發生的事。

Fellow 學伴從這個日常出發：先陪學生釐清不懂的概念，再在適當授權下協助尋找公共資源、提醒下一步，讓教師提早提供支持；最後以匿名聚合訊號協助公共部門改善資源服務。

![Fellow 支持旅程：學習提問、家庭資源、主動提醒、教師協助與匿名政策洞察](assets/story/support-journey.png)

## System Vision｜協助一路接得上，資料依用途分流

**產品願景：讓一次「我不懂」成為取得支持的入口。** 學習對話可以延伸到家庭主動提出的生活需求，但不能因此推斷或自動分享家庭隱私。每一次資料使用都應有明確目的、必要範圍與適當權限。

```mermaid
flowchart LR
    S[學生提出問題] --> L[學習引導與圖解]
    S --> F[學生或家庭主動表達需求]
    F --> R[公共資源與申請下一步]
    R --> N[授權後的相關提醒]
    L --> T[授權教學摘要]
    T --> H[教師判斷與協助]
    R -. 最小必要需求訊號 .-> A[匿名化與聚合處理]
    A --> G[政府理解區域需求]
    G -. 改善資訊與服務 .-> R
```

箭頭表示服務如何接續；家庭原始對話與個人資料依用途分流，不隨服務流程跨角色傳送。

| 核心功能 | 使用者操作 | 得到的支持 |
| --- | --- | --- |
| 01 學習問答與互動教學 | 提出氫鍵問題、說明想法、切換圖解並練習 | 找出卡點，依理解程度接續引導與確認 |
| 02 個人化公共資源推薦 | 自願描述家庭需求、比較資源卡與條件 | 了解可能適用的方向、推薦理由與申請下一步 |
| 03 主動通知與下一步提醒 | 選擇提醒範圍、查看相關事件與期限 | 讓重要資源及時出現，知道先確認什麼、向誰求助 |
| 04 教師端學生洞察 | 查看授權摘要、核對概念、安排教材與複習 | 更早發現需要支持的訊號，採取具體教學行動 |
| 05 政府匿名需求洞察 | 比較地區趨勢、資源缺口與流程指標 | 找到資訊阻力，作為改善政策服務的依據 |

## 01｜學習問答與互動教學：從「背得出名詞」到「說得出原因」

### 案例與問題：小晴分不清楚，水沸騰究竟改變了什麼

> 「課本說水分子裡有共價鍵，水分子之間又有氫鍵。既然加熱會把鍵弄斷，為什麼煮水不會煮出氫氣和氧氣？」

小晴記得名詞，卻把「一個分子內的原子連結」與「不同分子間的吸引」混在一起。再給她一遍定義，未必能看出她到底卡在哪裡。這個情境需要先聽見她的推理，再決定下一個問題。

### 系統如何介入：先讓學生表達，再決定教學方式

在這段 **蘇格拉底式互動教學** 中，AI 先提出短問題，依學生的回答判斷需要補哪一層概念；答對時增加解釋與應用，答錯時縮小問題並換圖解。

| 步驟 | 學生做什麼 | 系統如何回應 | 接下來觀察什麼 |
| --- | --- | --- | --- |
| 1 提出卡點 | 說出「氫鍵是不是 O–H 那條線？」 | 先請學生指出一個水分子內有哪些原子 | 是否能區分分子與原子 |
| 2 了解當下想法 | 描述自己認為的連結方式 | 用學生剛說的理由形成暫時教學判斷 | 哪個概念需要補充，而非替學生定級 |
| 3 引導推理 | 回答圖中實線與虛線連到哪裡 | 一次只追問一個關係，先不直接揭露整題答案 | 是否能辨別分子內、分子間 |
| 4 根據回答調整 | 答錯、猶豫，或提出正確理由 | 答錯時縮小範圍；答對時進一步問沸騰的變化 | 提示是否足夠、是否需要換方法 |
| 5 換說法與圖解 | 切換兩種視圖，對照生活類比 | 顯示 O–H 實線、分子間虛線，說明類比的限度 | 能否把圖與文字連起來 |
| 6 確認理解 | 回答新的小問題並說理由 | 核對理由；仍混淆就回到對應卡點 | 當次理解的證據與後續複習需求 |

![六步學習教學圖：提出卡點、了解想法、引導推理、調整問題、圖解、確認理解](assets/story/learning-steps.png)

### 八回合教學示例：答錯時，也有下一條路

**回合 1｜先定位卡點**

小晴：「氫鍵和共價鍵到底差在哪裡？我看不懂水沸騰那一段。」

學伴：「我們先看一個 H₂O。你認為氧和兩個氫是同一個分子裡的原子，還是三個分子？」

**回合 2｜聽見學生的原有想法**

小晴：「是同一個分子裡的原子，但 O–H 有氫，所以那條就是氫鍵吧？」

學伴：「你已經分得出一個水分子。接下來先不看名稱：圖上的 O–H 實線連在同一個水分子內，還是跨到旁邊的水分子？」

**回合 3｜發現答錯，降低問題複雜度**

小晴：「應該跨到旁邊吧？都是連著的，我還是分不出來。」

學伴：「先把旁邊的水分子藏起來，只留下這一組 O 和兩個 H。現在這兩條實線，有沒有連出這一組以外？」

**回合 4｜用已回答的線索補上名稱**

小晴：「沒有，兩條線都在這一組裡面。」

學伴：「對，水分子內的 O–H 實線表示共價鍵，涉及原子共享電子對。現在把第二個水分子放回來：虛線從第一個分子的 H 連到另一個分子的 O，這條線跨過了幾個水分子？」

**回合 5｜換生活類比，再回到圖中**

小晴：「兩個。但我還是很難記住它們怎麼分開。」

學伴：「把每個水分子想成一小組牽著手的人。不同小組彼此散開，不等於每一組內部鬆手。這個比喻只幫你區分『組內』與『組間』，不代表真實電子、鍵能或分子運動。回到圖上，組與組之間對應實線還是虛線？」

**回合 6｜回答正確，增加一層推理**

小晴：「虛線，所以這裡的氫鍵是在不同水分子之間。」

學伴：「在這個水的例子裡，是的。一般沸騰主要克服水分子間的吸引作用，包括氫鍵。照這個線索，分子進入氣相後，會仍是 H₂O，還是變成 H₂ 和 O₂？請說理由。」

**回合 7｜用理由確認，保留錯誤分支**

小晴：「仍是 H₂O，因為分子彼此分開，分子裡的 O–H 沒有因此被拆掉。」

學伴：「這個理由能區分相態改變與分解反應。若你剛才選 H₂ 和 O₂，我們會先回到只看一個水分子的圖，重新確認保留的是哪一條連結。」

**回合 8｜換一個小問題，檢查能否轉用概念**

學伴：「水蒸氣遇冷凝結為液態水時，需要先把氫氣和氧氣重新合成嗎？用一句話說明。」

小晴：「不需要，水蒸氣主要仍是 H₂O；凝結改變相態，水分子間的作用與排列改變。」

學伴：「你這次能用分子是否保留來解釋了。下次可再用不同例題確認；如果之後仍混淆，我們就回到分子內與分子間的圖。」

**化學閱讀提示：** 這裡以水比較分子內 O–H 共價鍵與分子間氫鍵，不把「有氫的鍵」都叫氫鍵，也不把所有氫鍵都限定在分子間；合適分子的內部也可能形成氫鍵。液態水中的氫鍵持續形成與斷開，圖上的虛線只是結構示意。一般沸騰是相變，與電解水的化學反應不同。相關原創教材見 [化學鍵與氫鍵資料](../../frontend/src/data/learningScenarios.ts)。

### Conversation Flow｜學生的回答決定下一個教學動作

```mermaid
flowchart TD
    Q[學生提出氫鍵問題] --> D[用短問題了解當下想法]
    D --> G[引導分辨分子內與分子間]
    G --> S[學生回答並說理由]
    S --> J{目前回答的證據}
    J -->|混淆或不知道| E[縮小問題：只顯示一個水分子]
    E --> V[生活類比加圖解，說明類比限度]
    V --> G
    J -->|能解釋基本關係| A[進一步問沸騰後是否仍是 H₂O]
    A --> C[換一題確認：凝結是否要重新合成水]
    C --> R{能否說明理由}
    R -->|仍混淆| E
    R -->|當次能合理說明| F[小結與後續複習；必要時邀請教師協助]
```

一次答對提供當次理解的線索，後續仍需用新題目確認。重複卡住時，學生可以暫停、換教材或找教師協助。

### 最終價值

小晴逐步說出「為什麼」，也能在不懂時選擇另一條學習路徑。提問、教材依據、可操作圖解與確認理解共同構成教學過程，讓學生把名詞連到圖形，再轉用到新問題。

## 02｜個人化公共資源推薦：把「不知道能問誰」變成可採取的下一步

### 案例與問題：氫鍵問懂了，明天的學費仍讓小晴擔心

小晴的家庭從事農業，近期收入下降。她知道家裡正在節省開支，卻不知道學費、午餐費能不能尋求協助，也不知道「助學」「急難」「社福」應該先問哪一個窗口。

> 小晴：「家裡最近收入變少，學費和午餐費有點困難。我不知道有沒有可以問的地方。」

這個需求由小晴**主動提出**。系統不能因為她氫鍵答錯、提問頻繁或學習速度較慢，就推斷家庭經濟困難、健康狀態或需要社福服務。

### 系統如何介入：先問最少的問題，再整理候選方向

學伴先說明用途，再用少量追問找出下一步所需資訊；收入證明、身分文件等正式申請材料，留待確認方案後由合適窗口處理。

> **學伴：**「我可以先整理就學與生活支持方向。為了找對窗口，你願意提供就讀學制、所在縣市，以及目前最急的費用項目嗎？不知道或不想提供的可以先跳過。」<br>
> **小晴：**「我是高中生，住在甲縣。午餐和這學期的學費最急，家裡務農。」<br>
> **學伴：**「我會先整理校內就學協助，再列出生活支持窗口。目前還不知道各項方案的條件與受理期間，所以只能標示『待確認』。」<br>
> **學伴：**「你也可以選擇是否讓我記住『家庭從事農業』，方便下次整理相關資源；這次查詢與長期記憶是不同用途。」

資源清單先提供求助方向；資格、文件與受理期限依選定方案及承辦窗口確認。

### Step-by-Step｜從生活困難走到一份可詢問的清單

| 步驟 | 小晴與家庭的操作 | 系統如何回應 | 畫面上的成果 |
| --- | --- | --- | --- |
| 1 說出情境 | 描述收入變動與學費、午餐壓力 | 先整理使用者表達的需求，說明需要哪些資訊及用途 | 「優先需求：就學費用、基本生活」 |
| 2 補充必要資訊 | 自願提供學制、概略地區及急迫事項，可跳過未知項目 | 將已知與待確認條件分開，不要求先交完整家庭文件 | 「已知：高中在學；待確認：適用方案與時程」 |
| 3 比對資源 | 查看不同方向，也可自行切換分類 | 比對需求、地區與已提供的條件，保留可能相關項目 | 可比較的候選資源與推薦理由 |
| 4 決定優先順序 | 確認目前想先處理哪一項困難 | 按需求急迫性、資訊可信度、條件相關性與已核實期限安排順序 | 「先問校內窗口；並行了解基本生活支持」 |

## 03｜主動通知與下一步提醒：讓資源主動找到可能需要的人

### 案例與問題：小晴還在準備化學小考，家裡已開始擔心風雨

完成氫鍵複習後，小晴回到日常課業。她在上一段資源諮詢中，自願保存「家庭從事農業」，並另外同意接收與所在地相關的資源提醒。案例中，一場颱風接近甲縣，家人忙著照顧作物，未必有時間逐一追蹤公告。

風雨過後，若家庭遭遇農損，可能需要了解農業災害救助、災後貸款或地方緊急協助。但不同方案的地區、作物、損失認定與受理期間都可能不同；知道「有補助」與知道「現在該確認什麼」之間，仍有距離。

### 系統如何介入：分清楚事件提醒與已公告的資源

系統結合使用者同意使用的資料與經查核的公開資訊，判斷可能相關的方向；「家庭務農」只是相關性線索，不能直接推定受災、符合資格或應該申請貸款。

| 時間點 | 系統取得的資訊 | 適合的回應 | 仍不能推定的事 |
| --- | --- | --- | --- |
| 颱風前 | 經查核的天氣或地方防災資訊，且涵蓋家庭自願提供的地區 | 提供有來源的防災資訊入口；註明目前尚未確認救助公告 | 不能把颱風預報說成救助已開放，也不能假設家庭一定受災 |
| 颱風後、尚無可核實公告 | 當地可能受影響，但尚缺正式方案資訊 | 顯示「救助資訊待確認」，提供可詢問的地方窗口 | 不能自行補上資格、補助額度或申請期限 |
| 災後、已有經查核公告 | 公告涵蓋的地區、對象、期間與窗口可核對 | 推薦可能相關方案，說明比對理由，再請家庭核對條件 | 公告涵蓋地區不等於每個家庭或每種作物都符合 |

### Step-by-Step｜從相關事件走到可以執行的下一步

| 步驟 | 小晴與家庭的操作 | 系統如何回應 | 產生的下一步 |
| --- | --- | --- | --- |
| 1 選擇提醒範圍 | 同意使用概略地區與務農資料，可選擇不接收 | 分開記錄資料用途與提醒偏好 | 使用者知道提醒依據，也能撤回 |
| 2 系統確認事件與來源 | 不需要先知道政策名稱 | 核對官方來源、發布與更新時間、適用地區及受理期限 | 只有可核實資訊才形成政策推薦 |
| 3 判斷是否可能相關 | 必要時自願補充作物或受影響情況，也可跳過 | 比對已知條件；未知項目保留「待確認」 | 有推薦理由與條件缺口的通知 |
| 4 閱讀通知 | 查看「為什麼提醒你」並開啟詳情 | 以六項重點整理可能方案 | 家庭能判斷是否值得進一步詢問 |
| 5 確認資格與準備事項 | 向公告所列窗口確認條件、文件與時程 | 提供可照讀的詢問句；若無法核實，保留人工求助入口 | 正式準備清單由實際方案與承辦窗口確認 |
| 6 選擇後續提醒 | 可選稍後提醒、停止此類提醒或自行記錄進度 | 只依已核實期限安排提醒；進度若由使用者回報，註明來源 | 家庭自行申請或尋求協助；系統不代為送件 |

### 一則通知應回答六個問題

> **農業災害協助方向｜公告待查核**<br>
> **1. 為什麼收到：** 你曾同意使用「家庭從事農業」及「甲縣」資訊接收相關提醒；本次事件可能影響這個地區，是否受災仍需你確認。<br>
> **2. 哪項政策可能相關：** 農業災害救助；也可向窗口詢問是否另有地方緊急協助或災後貸款，條件各自確認。<br>
> **3. 申請資格：** 待確認；需核對當次公告的地區、作物、對象與損失認定方式，家庭務農不等於已符合。<br>
> **4. 截止日期：** 待查核；尚未取得有效公告，不顯示倒數，也不推定現在可申請。<br>
> **5. 準備文件：** 待公告與窗口確認；可先整理想詢問的作物、所在區域及受影響情況，是否需要身分、耕作或損失資料依實際要求辦理。<br>
> **6. 申請窗口與下一步：** 先向所在地公所詢問：「家裡務農，這次風雨後想確認有無適用的救助公告、受理時間，以及應準備哪些資料？」正式送件依公告指定窗口辦理。

取得可核實公告後，通知會補上正式名稱、來源連結、查核時間、明確期限與受理窗口。救助與貸款分開說明，家庭可依自身需求向窗口確認。

**期限提醒教學：公告資料完整時，期限如何變成行動？** 以下以政策 A 為例，D0／D10／D14 表示案例中的相對天數。實際受理期限以有效公告為準。

| --- | --- | --- |

### 最終價值：讓重要資源有機會及時抵達

**把「等使用者找到資源」，改成「讓資源主動找到可能需要的人」。** 小晴不必在準備化學小考時，同時知道每一項政策名稱；一則有理由、可查核、有下一步的提醒，讓家庭多一個取得協助的入口。

## 04｜教師端學生洞察與即時協助：在下一次考試之前，先看見可以幫忙的地方

### 案例與問題：小晴願意練習，卻又把分子內與分子間混在一起

小晴在第一次氫鍵教學中，已能說出「水沸騰後仍是 H₂O」。但隔幾天換成另一張分子圖，她又把跨分子的虛線認成 O–H 共價鍵，需要教師縮小圖的範圍後才能分辨。一次答對與換題後仍能解釋，是不同的觀察。

如果只等考試成績下降，教師可能較晚才知道她缺的是「分子內／分子間」的基礎概念。教師需要的是能核對的線索：哪個概念值得再問、哪些回答需要提示、換了什麼說法後能繼續推理；這些線索應連到教學行動。

| 發現問題的時機 | 教師取得的訊息 | 可以採取的行動 |
| --- | --- | --- |
| 常見情境：考試之後 | 分數下降，但還不知道卡在哪一步 | 再找時間回看題目、詢問學生 |
| 學習過程中 | 可追溯的概念觀察與待確認事項 | 在下一堂課或課後先確認分子內／分子間概念 |

### 系統如何介入：把訊號交給教師，也把不確定性一起交代

學伴先限定教師可查看的班級與教學用途，再整理主題摘要及建議。每個「值得關心」的提示都應能回答：資料來自何時、觀察到了什麼、還缺什麼證據，以及教師可以怎麼確認。

| 觀察層次 | 氫鍵案例中可呈現的線索 | 教師應如何解讀 |
| --- | --- | --- |
| 當次觀察 | 小晴在圖解後能說明「沸騰不會把水分子拆成氫氣、氧氣」 | 有當次理解的理由，尚不能宣告長期掌握 |
| 跨次觀察 | 不同日期、不同圖形下又混淆分子內／分子間，且保留題目與回答依據 | 值得安排基礎概念確認；不能只看同主題提問次數 |
| 提示與教法觀察 | 隱藏第二個分子後能判斷實線位置，再看雙分子圖仍需追問 | 圖形拆解「可能有幫助」，不是固定學習風格或已驗證成效 |
| 證據不足 | 只有提問紀錄，沒有實際作答、提示歷程或後續確認 | 明示「待觀察」，不能填成零分、未看完或不努力 |

### 一段師生對話：從「需要關注」回到學生怎麼想

> **教師：**「這個主題值得再一起確認。你可以先圈出圖中的一個 H₂O，再說說 O–H 實線連在哪裡嗎？」<br>
> **小晴：**「實線都在同一個水分子裡。我看到兩組放在一起就容易認錯。」<br>
> **教師：**「我們先分開看，再把第二組放回來。你畫出跨到另一個水分子的虛線，說明這裡的氫鍵位置。」<br>
> **小晴：**「虛線跨了兩個水分子。沸騰時分子彼此分開，但分子內 O–H 還在。」<br>
> **教師：**「這次說得清楚。我們下次換張圖再確認；如果還會混淆，就用課後時間慢慢拆開看。」

## 05｜政府匿名需求與政策洞察：從區域訊號，找到服務可以改善的地方

### 案例與問題：很多家庭都在找協助，承辦人看得到什麼

小晴的故事走到這裡，政府端不會出現她的姓名、氫鍵對話或家庭求助內容。公共部門需要看到的是：某個地區是否出現值得進一步了解的需求變化，以及民眾取得資訊之後，哪一步仍需要協助。

**情境 A｜農業、急難與學費的需求訊號一起增加。** 颱風之後，甲縣的甲區出現更多農業災害救助、急難協助與學費支持相關互動。範例數據中，農業救助訊號由相同長度前期的 **40 次**增加至本期 **100 次**。承辦人可以先核對災情、服務窗口詢問量與平台使用變化，再決定是否加強資源說明與服務量能。

**情境 B｜政策已公布，取得協助的過程仍不順。** 承辦人想知道：家庭是否不知道政策、看不懂文件要求，或在申請中途遇到困難。將取得資訊、開啟詳情、開始申請到確認送件串成漏斗，可協助辨識需要再調查的步驟；指標必須來自合法授權、可核對的流程資料。

**數據解讀：** 40 → 100 是範例中的互動需求訊號次數，不是受災戶、獨立家庭或申請人數。平台使用量、重複提問、季節與宣傳活動，都可能影響數字。

| --- | --- | --- | --- |

| 6 再觀察 | 追蹤相同定義、相同長度期間 | 查看聚合與追蹤清單 | 確認變化是否與改善有關，避免只憑前後差異宣稱成效 |

<a id="anonymous-insights"></a>

### Anonymous & Aggregated Insights｜先說清楚分子與分母

**申請漏斗計算範例：** 以同一批次、同一觀察窗內去重且可核對的資料為例：100 位看到資訊 → 60 位開啟詳情 → 30 位開始申請 → 12 位確認送件。此處使用範例數據說明指標計算。

| 想看什麼 | 計算範例 | 正確解讀 |
| --- | --- | --- |
| 開始申請後的確認送件比例 | 12 ÷ 30 = **40%** | 分母是該批次開始申請者；只描述觀察窗內確認送件的比例 |
| 尚未確認送件比例 | (30 − 12) ÷ 30 = **60%** | 可能仍在準備、回傳延遲或改走其他管道，不能稱為已放棄 |
| 正式政策觸及率 | 已確認觸及的符合資格人數 ÷ 合法取得的符合資格母體 | 必須同時具備資格母體與去重觸及資料；不是 60 ÷ 100 的替代名稱 |

**事件與人數分開看：** 同一家庭可能產生多次互動。平台事件比率描述互動紀錄，政策觸及率需要符合資格的母體，申請完成率需要可核對的申請流程；三者不能互相替代。

確認送件不等於核准，也不等於已領取補助。樣本或母體不足、前後定義不一致、來源不可核對時，應顯示「資料不足」並不顯示百分比；前期為零也應呈現筆數與限制，不使用誤導性的成長率。小群體是否可發布還要另經隱私檢查。

```mermaid
flowchart TD
    E[內部需求事件：限制存取的來源資料] --> A[按日、地區與主題聚合計數]
    A --> P[發布檢查：小群體抑制與重識別防護]
    P --> G[可發布的區域趨勢與資料限制]
    G --> Q[承辦核對災情、使用量與服務資訊]
    Q --> H[提出資訊缺口假設]
    H --> I[人工審查並改善說明或服務]
    I --> O[按相同定義再觀察]
    O --> Q
    F[合法授權的申請流程回傳] -. 同批次、同觀察窗與可信母體 .-> M[申請漏斗與政策觸及指標]
    M -. 經相同發布檢查 .-> G
```

## Privacy & Data Protection｜使用者應知道誰看得到什麼

小晴可以取得氫鍵教學，也可以選擇是否保存家庭務農資料。她同意一項記憶，不代表已同意教師查看家庭對話、接收所有通知，或把所有內容轉作政策分析。產品需要把這些用途分別說清楚。

![資料權限：學生自己的內容、教師授權教學摘要、政府區域聚合](assets/story/data-boundaries.png)

以下矩陣說明三種角色的資料可見範圍。教師需要教學摘要，政府需要區域趨勢，兩者各有明確用途。

| 資料 | 學生本人 | 教師角色 | 政府角色 |
| --- | --- | --- | --- |
| 自己的學習及資源對話、引用 | 可查看自己的紀錄 | 只取得授權教學提問與摘要，不含家庭資源原始對話 | 不提供 |
| 上傳圖片 | 本人驗證後可下載 | 不提供學生原始附件 | 不提供 |
| 家庭特徵與同意的個人記憶 | 可查看、修改個人資料並刪除記憶 | 不提供家庭經濟資料或私人記憶 | 不提供 |
| 學生姓名、班級與教學摘要 | 可查看自己的個人學習內容 | 限授權班級；CSV 含姓名等教學資料 | 不提供名冊、姓名或學生 ID |
| 日期／地區／主題的聚合計數 | 不是學生端工作台功能 | 不是政府聚合的替代入口 | 可篩選、查看與匯出，不能鑽取個人 |

### 使用者控制：每一種用途，都說明清楚

| 控制項目 | 使用者需要理解的事 | 服務應交代的內容 |
| --- | --- | --- |
| 是否保存記憶 | 這次查詢與長期保存家庭特徵是不同用途 | 保存什麼、用在哪裡，以及如何拒絕或刪除 |
| 更正與撤回 | 資料可以更正；同意的範圍可以重新選擇 | 撤回影響哪些後續推薦、提醒與資料處理 |
| 刪除資料 | 刪除記憶、對話與附件各有不同範圍 | 已處理項目、保存期限、備份與已發布聚合的處理方式 |
| 教師存取 | 教師只查看授權班級的教學資料 | 誰可存取、為何存取、匯出後如何保管 |
| 政府聚合發布 | 政府取得區域趨勢，不能鑽取個人 | 小群體、敏感組合與重複查詢的發布檢查 |

**匿名化不只移除姓名。** 小地區、少數事件與多次篩選仍可能讓人推測個別情況。發布前須依資料風險檢查最小群體、時間與地區粒度，必要時合併或不顯示結果，也要限制跨次查詢可推算出的差異。

```mermaid
flowchart LR
    P[本人對話與家庭資料] --> S[依身分、用途與範圍控制存取]
    S --> T[教師授權班級的教學摘要]
    S --> E[政策分析所需的最小必要訊號]
    E --> A[按日、地區與主題聚合]
    A --> R[小群體、差分推算與重識別發布檢查]
    R --> G[政府查看區域趨勢與計數]
    C[使用者選擇資料用途] --> D[記錄同意、更正、撤回與刪除範圍]
    D --> S
```

## End-to-End User Journey｜支持最後回到小晴的日常

| 故事節點 | 小晴與周圍的人經歷了什麼 | 可展示的產出 |
| --- | --- | --- |
| 一個晚上 | 小晴問「氫鍵是不是 O–H 那條線」，從單一水分子看起 | 圖解、追問與對凝結的新解釋 |
| 另一次主動求助 | 她說出學費與午餐壓力，選擇是否提供或記住家庭資料 | 候選資源、待確認條件與可照讀的詢問句 |
| 一次相關事件 | 經授權與公告查核後，家庭收到農業協助提醒 | 推薦理由、期限及聯繫窗口的下一步 |

| 一次服務改善 | 承辦從區域聚合提出疑問，核查後改善資源說明 | 家庭更容易找到、讀懂與使用的服務入口 |

```mermaid
flowchart TD

    L --> T[教師更早核對學習需要]
    T --> L
    F -. 合適用途下的最小必要訊號 .-> A[匿名化、聚合與發布防護]
```

教師提供教學支持、家庭決定是否求助，政府改善資源服務。這個循環讓學習與生活上的支持接續下去，三種角色各自保有判斷與資料邊界。

## Overall System Architecture｜同一個系統，依用途產生不同回應

```mermaid
flowchart TD
    W[三角色介面<br/>React · TypeScript · Vite] --> API[同源代理與 FastAPI<br/>Session · 角色 · 範圍檢查]
    API --> AG[學習與資源 Agent<br/>路由、檢索與教學回應]
    AG --> R[教材與資源檢索]
    R --> C[(Chroma<br/>教材與資源索引)]
    J[教材與公共資源內容] --> R
    AG --> DB[(SQLite<br/>對話、個人資料、通知與內部事件)]
    API --> IMG[私人圖片<br/>擁有者驗證後提供]
    DB --> TS[教師服務<br/>授權班級的教學摘要]
    DB --> GS[政府服務<br/>事件按日、地區與主題聚合]
    TS --> TO[教師介面<br/>名冊與教學摘要]
    GS --> GO[政府介面<br/>限定維度與計數]
    F[模型與外部服務<br/>官方來源 · 事件資訊<br/>提醒排程 · 申請回傳] -. 服務整合 .-> API
```

三種角色共用服務入口，依身分、範圍與用途取得不同回應。教材與資源檢索支援學生提問；教師服務提供授權教學摘要；政府服務提供限定維度的聚合結果。外部模型、官方來源與事件資訊透過服務介面整合，元件版本詳見文末對照。

### 學習與資源

- 學習支援牛頓力學、熱力學、熵、化學平衡、化學鍵結、反應速率六個主題及既有追問。自適應追問、動態難度、跨次理解驗證與教法效果比較尚未完成；超出支援範圍會提示限制，後續可以與出版商合作。
- 可上傳並保存 JPEG／PNG，但離線回答只根據文字，不執行 OCR 或圖片理解。前端練習能顯示正誤，作答與動畫完成狀態尚未回傳成正式學習觀察。
- 資源推薦依個人資料的類別訊號與地區判斷是否列入清單，按類別、標題排序；急迫性評分、完整資格審查、跨方案最佳化與完整人工轉介流程尚未完成。
- 離線政策未將午餐補助、弱勢學生補助、獎助學金各自建成完整獨立方案；種子資料沒有已查核官方 URL 或更新日期。「查看政府來源」目前提供來源片段與查詢文字，不代表已完成官方政策串接。清單勾選不等於送件，系統不代為聯絡或建立申請案件。

### 通知與教師工作台

- 通知中心讀取預載資料，依地區、務農特徵、`active_from`／`expires_at` 篩選並保存已讀。農業通知以「美濃」作為資料比對範例；種子通知未設定截止日，不能據此認定現行政策仍有效。
- 官方事件串接、來源查核、公告版本去重、提醒偏好、安靜時段、排程、Email／LINE／SMS 推播與申請進度追蹤尚未完成。「從列表移除」只在本次頁面暫時隱藏，重開頁面會恢復；刪除記憶可更正後續比對資料，但不會刪除既有已讀紀錄，也不是獨立訂閱控制。
- 教師 API 先限定授權班級，再提供名冊及教學摘要，不回傳家庭資源原始對話。新提問的 `practice_correct`、`animation_completed` 為空值；`learning_gap` 是互動訊號，單一訊號也可能觸發「需關注」。詳情頁中的低正確率文字仍須核對實際作答分母，不能視為診斷。
- 教師複習計畫與偏好只保存在瀏覽器 `localStorage`，未同步後端、未自動通知學生。政府追蹤清單與部分偏好亦保存在各自瀏覽器。清除資料或換裝置無法沿用；完成複習是教師工作紀錄，不是學生掌握度評量。
- 教師與政府頁透過 API 讀取當時摘要，沒有即時串流或推播。跨次教學證據、提示次數、介入成效、更正流程及校內轉介仍需補齊。

### 政府指標與匿名化

- 政府範圍固定為高雄六區：甲仙、六龜、杉林、美濃、旗山、內門；正文「甲縣／甲區」為案例地名。工作台與既有截圖包含範例計數，尚無正式政策資格母體、去重觸及或申請流程回傳，不能計算正文的正式觸及率與申請漏斗。
- `resource_need_count` 計入資源需求與資源興趣事件；`resource_view_count` 表示資源興趣事件，不是正式申請頁面瀏覽或送件紀錄。介面「資源觸及率」是已開啟資源需求事件除以全部資源需求事件的**平台事件比率**，不是符合資格家庭的政策觸及率。每個事件歸入一個主要主題，同一家庭仍可能有多次事件。
- 後端直接從 `InsightEvent` 依日期、地區、主題做 SQL 聚合；政府 API 與 CSV 不含姓名、學生 ID 或原始對話，也無個人鑽取入口。內部事件仍保存 `user_id`、`message_id` 與來源關聯，因此內部資料庫尚非不可逆匿名化。
- 小群體抑制、重複篩選與差分推算防護、敏感組合限制、發布審查及重識別測試尚未完成。正文隱私流程包含正式使用所需的發布保護，不能以現有聚合輸出宣稱已保證匿名性。

### 身分、同意與資料保存

- API 檢查角色、教師班級與私人圖片擁有者；離線入口使用固定角色身分，正式帳號、組織授權、存取稽核與維運權限仍需完成。資料目前保存於 SQLite 與私人附件儲存。
- 記憶建議經接受才寫入並保存同意時間；拒絕記憶不會刪除本次對話。刪除記憶會清空相應個人資料欄位，不連帶刪除歷史對話、附件、洞察事件或通知紀錄。
- 教學、提醒、政策分析的跨用途同意、撤回連動、完整刪除、保留期限、備份與來源關聯清理，仍需完成並驗證。已發布聚合的處理方式也需另行明確訂定。
