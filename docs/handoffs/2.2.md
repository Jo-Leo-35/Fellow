狀態：Subtask 2.2 完成。Core APIs、最小可驗證 session/auth、persisted usage 基礎、private upload 與兩種 dashboard snapshot 已完成；沒有實作或假裝完成 Agent/LLM/RAG pipeline。

## 完成內容

- 註冊固定契約中的全部 core routes：profile GET/PUT、memory 明確 consent/delete、conversation list/detail/delete、resource list/detail、learning materials、alert list/read、JPEG/PNG upload/private content、teacher/government dashboard，以及 core route 使用所需的 session exchange/session check/usage。
- 建立最小 server-configured Demo gate：`DEMO_ACCESS_CODES` 是 `config_key -> secret code` 的 server-side JSON map，值以 `SecretStr` 載入；source、seed、測試皆沒有固定可用 code。沒有任何設定值時所有交換都回 401 `INVALID_ACCESS_CODE`。
- Access code 只選到 DB `demo_principals.config_key`；subject、role、daily limit 與 teacher classes 再由 DB principal/user/scope 決定。成功交換產生 48-byte 隨機 opaque token，DB 只保存 SHA-256 hash；session 最長 8 小時、可過期/撤銷，全部 protected route 從 Bearer session 建立 principal，不預設 request 是 Demo student，也不接受 role header。
- `GET /usage` 以 principal + 真實 UTC 日窗查詢/建立 `quota_ledgers`，回 DB 的 limit/used/reserved/remaining/reset_at；重複登入不重設。沒有用虛構常數冒充已持久用量。Task 4.1 的原子 reserve/finalize/release 尚未提前實作。
- Profile PUT replace user/profile 的全部 editable fields；字串 trim、空 optional 值歸 null，Pydantic 保留 nickname/grade/array/extra-field 驗證。所有 path/query `user_id` 都必須等於 session subject。
- Memory 只接受本人、DB 中存在、尚未過期、allow-list key、status pending 且 JSON literal `consent:true` 的 server-issued suggestion。第一次接受為 201；同 suggestion 已成功接受可重試並以 200 回同 item，不重寫。過期為 409；錯誤 owner 為 403；拒絕/validation 不寫 profile memory。
- Memory consent 同步寫入對應 persisted profile feature；DELETE idempotent 204，並清除同一 profile/user feature。舊 suggestion 會失效，因此後續 retry 不會在使用者刪除後把資料復活。Resource/alert matching 都讀 persisted feature，所以刪除後不再沿用舊記憶推薦或通知。
- History list 支援 1..100 limit 與 owner-bound opaque conversation cursor。Detail 只組裝 DB 中 message `structured_response`、`source_snapshot`、follow-ups、attachment snapshot，不呼叫 Agent、不檢索、不寫 Insight/usage。Delete 依既有 FK cascade/SET NULL：message 刪除，但已 consent memory、learning activity 與 Insight 保留，memory source conversation 變 null。
- Resource list/detail 從 `policy_programs` 建 canonical `ResourceProgramWire`/policy source。`recommended_only` 使用 authenticated persisted grade/occupation/family/economic/identity/normalized region signals；沒有 signal 可回 `items:[]`。沒有正式 profile/rule 證據時 status 保守為 `needs_confirmation`/`possibly_eligible`；即使 catalog 未來含 `eligible` 也會降為 `possibly_eligible`，沒有使用 embedding 判定資格。
- Alert list 依真實 UTC active/expiry、normalized region、student/farmer persisted feature matching；unknown target/region 不猜測。Read state 用 `(alert_id,user_id)` persisted row，重複 mark-read 回相同 read timestamp；`unread_only` 與總 unread count 一致。
- Upload 上限 5 MiB；先檢查 declared MIME 與 JPEG/PNG magic，再以 Pillow verify + full decode 且限制 40MP。格式不支援/不一致為 415、損毀/不可解碼為 422、過大為 413，皆走統一 error envelope。顯示檔名移除 path/control characters並依實際格式換 extension；attachment/storage key 隨機，response 不含 server path。
- Image content 每次重驗 student owner，以 private/no-store、nosniff、正確 Content-Type/Length 回 bytes。未連到 `message_attachments` 且超過真實 UTC 24 小時的 orphan upload，會在 app startup 安全清除；DB commit 失敗也會清掉剛寫入檔案。TTL 可由 `UNATTACHED_UPLOAD_TTL_HOURS`（1..168）設定。
- Teacher snapshot 先從 session teacher id 查授權班級，未授權 class 為 403，再套 period/class/subject/threshold。`question_count` 是 activity row；practice/animation 分母只計 boolean 非 null，0 分母回 null。`gap_count` 只計真正 learning-gap Insight。新增 null-observation learning question 的整合測試證明只增加 question；建立實際 primary gap 後才增加 gap，不增加 practice/correct/animation。
- Teacher response 提供 contract 所需 authorized scope、filter options、current/previous summary、六主題 metadata、完整授權 roster/topic summaries/status、trend；不查/輸出家庭 profile、經濟資訊、raw conversation、message text 或 upload。
- Government snapshot 的 service query 在 SQL 端以 `date(occurred_at)`、allow-list normalized `region`、known `government_topic` group by，只選出這三個維度，以及 `count(*)`、resource need/interest、potential need、resource view 的 conditional sum。Service 收到的每列只有日／區／主題／四個 aggregate count，不 materialize raw `InsightEvent`，也不 select identity/source 欄位或 join user/profile/roster/conversation/message/upload。Null/未知 region/topic 排除，不預設地區。Current/previous 是連續相同天數，totals/topics/regions/trend/daily aggregate 使用同一份 DB 聚合 projection；Agent insight 文案也只由這些 aggregate counts 衍生。
- Offline Demo 的 teacher/government `as_of` 與 dataset windows 使用 2.1 stored anchor；session expiry、suggestion expiry、alert read、upload TTL、daily quota/reset_at 全部使用真實 UTC。沒有用 seed anchor 凍結安全/用量時間。

## API routes

- Public：`POST /api/v1/auth/demo/session`。
- 任一有效 session：`GET /api/v1/auth/session`、`GET /api/v1/usage`。
- Student self：`GET|PUT /api/v1/profile/{user_id}`、`POST /profile/{user_id}/memory`、`DELETE /profile/{user_id}/memory/{key}`。
- Student self/owner：`GET /conversations`、`GET|DELETE /conversations/{conversation_id}`、`GET /resources`、`GET /resources/{program_id}`、`GET /alerts`、`POST /alerts/{alert_id}/read`、`POST /uploads`、`GET /uploads/{attachment_id}/content`。
- Student/teacher：`GET /api/v1/learning/materials`。
- Teacher：`GET /api/v1/dashboard/teacher`。
- Government：`GET /api/v1/dashboard/government`。

所有 route 均使用 2.1 的既有 `app.schemas.*` response/request model；list 無資料回 200 + `[]`，只有成功 DELETE 回 204。FastAPI request validation 與 AppError 都由既有 handler 轉成固定 error envelope。

## 3.1 可直接使用的 persist / Insight 接點

- Request/session：router dependency 使用 `DbSessionDependency`、`StudentPrincipalDependency`；authenticated `current.user/current.principal/current.auth_session` 是唯一 identity source。Agent request 的 compatibility `user_id` 仍須呼叫 `require_self()`；conversation/attachment ownership 必須在 quota reserve 前檢查。
- Structured replay：`Conversation`/`Message` 的 `structured_response`、`source_snapshot`、`suggested_follow_ups`、`attachment_ids_snapshot` 是 canonical history snapshot。3.1 必須同 transaction 寫 user/assistant messages與 `MessageAttachment` link；不能讓 history service重建內容。
- Learning/Insight：`app.services.insights.record_learning_question()` 新增 message-linked activity，固定把 practice/animation observation 寫 null；`learning_gap_projection()`、`resource_projection()` 執行固定 taxonomy/eligibility flag。`resource_projection()` 對 `resource_interest` 一律產生 `potential_need=False, resource_view=True`，不受 eligibility status 影響；對 `resource_need` 僅在 `possibly_eligible`／`needs_confirmation` 時產生 `potential_need=True`，且一律 `resource_view=False`。`record_primary_insight()` 驗證 assistant/conversation/owner 一致，region 保守 normalization，occurred_at 強制取 assistant message timestamp，且不自行 commit。
- `record_learning_question()` / `record_primary_insight()` 刻意由 caller transaction 管理。3.1 應在同一 transaction 完成 conversation/messages/snapshot、至多一個 activity/primary Insight 與 quota finalize；existing unique constraints仍是最後防線。
- Resource `other` 預設不產生 government topic；只有已判明目前 Demo 社福/生活支持語意時才傳 `other_is_social_support=True`。Education 只有明確升學語意才傳 `admission=True`。

## 4.1 仍須加固

- Access exchange 尚無 rate limit、失敗稽核/lockout、code rotation policy；token hash 尚無 server pepper。Session 沒有 logout/revoke endpoint、last-seen batching或 expired-row cleanup。這個 2.2 gate 可直接驗證，但不是正式帳密/IAM。
- Quota 目前只有真實 persisted daily ledger read/create。4.1 必須用 DB conditional transaction完成 reserve/finalize/release、reservation recovery與 canonical `/agent/chat`/`/chat` operation；同時完成至少 24h idempotency lifecycle，不能只用 process lock。
- Rate limit/Agent timeout 需用真實或 monotonic clock；不得使用 Demo anchor。CORS 的 allow methods/headers、request/body limits、安全 headers與 production secret要求仍由 4.1 收斂。
- Orphan upload cleanup目前在 process startup執行。4.1/4.2 若要長時間不重啟，應接 scheduler；3.1 必須在持久 assistant transaction中寫 `MessageAttachment`，否則超過 TTL 的未連結 upload會依 policy回收。
- 沒有 Alembic migration；延續 2.1 `metadata.create_all()` 限制。
