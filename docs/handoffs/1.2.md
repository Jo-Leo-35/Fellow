## 完成內容

- 依 `docs/api-alignment.md` 固定契約完成完整 snake_case wire types 與 camelCase view types，涵蓋 Demo session、usage/quota、Agent structured response、learning/source、resource list/detail、profile/memory、conversation list/detail/replay、alerts、upload、teacher snapshot 與 government aggregate snapshot。
- 保留 `src/types/index.ts` 原有 `StudentNavKey`、`ResponseType`、`LearningAnswer`、`ResourceRecommendation`、`MemorySuggestion` export；新契約另由 `wire.ts`／`view.ts` 明確 export，沒有把原本簡化 type 假裝成 richer API payload。
- 建立逐欄位 adapter；沒有 generic recursive case converter，也沒有 import/執行 `src/data/` 的 Demo generator。Learning 保留 `steps.body/sourceIds`、formula、analogy、misconception、practice、follow-ups；resource 保留 eligibility checks/status、reasons、missing conditions、window、documents、deadline、next step 與 sources。
- Learning adapter 對未知 `scenario_id`／`animation_topic` 不強轉動畫 key：known key 放入 `scenarioId`／`animationTopic`，unknown 值保留於 `unrecognized*`，安全動畫 selector `id` 為 `null`。必要 array 或 primary structured payload 缺失會拋出明確 `ApiContractError`，不靜默換成本機假資料。
- Teacher adapter 原樣保留 `practiceCount`、`correctCount`、`animationObservationCount` 與 nullable percentage，不用 question count 推算作答正確率，也不把未知結果變成 `false`／`0%`。Government view 只包含 aggregate dimensions/count/percentage/trend/insight，沒有 raw event 或個人／對話欄位。
- 強化 Fetch client：`VITE_API_URL` 可覆寫，預設 same-origin `/api/v1`；base/path 斜線正規化；`Headers` 合併；Bearer token memory + `sessionStorage`；401 清 session；沒有 VITE token、內建 token、角色 header 或 secret。
- JSON、FormData、binary response 各有獨立 helper。Multipart 一律移除手動 `Content-Type`，讓 browser 產生 boundary；圖片內容下載仍帶認證。一般 15 秒、upload 30 秒、Agent 45 秒 timeout 與 caller abort 都覆蓋完整 response lifecycle，包括 headers 後的成功 JSON body、非 2xx error body 與 binary body；並保留 network error、204/205/empty response 與 malformed success JSON 分類。
- `ApiError` 保留 HTTP status、server code/message、request id、retryable、runtime mode、typed details、usage 與 `Retry-After`；另支援 FastAPI/Pydantic `detail` validation fallback，不把非 envelope server body直接顯示。
- 為全部 21 個契約 route 建立 typed API object/function。主要聊天為 `agentApi.chat()`；`chatCompatible()` 只提供 `/chat` alias。Profile memory 只有明確 `acceptMemory()`（固定 `consent:true`）與 delete，拒絕不需要 API。
- Agent request 必填 `idempotencyKey`。`createAgentSubmission()`／`submit()` 與 module-level registry 讓同一 stable submission 共用同一 transport 與 completed result；每個 consumer 的 `signal` 只取消自己的等待，不會中止其他 consumer 或污染之後的同 submission consumer。`getSubmission()` 可在 navigation 後訂閱同一結果而不重送首題；失敗 entry 會移除以容許同 key 安全重試。只有明確的 `cancelSubmission()` 會取消整個使用者動作；session 清除／token principal 切換則取消 pending transport 並清除 retained submission，避免跨 session 保留結果。

## Task 2 / backend 必須知道

- 必須逐字配合 `src/types/wire.ts` 與 `docs/api-alignment.md` 的 canonical snake_case schema、nullable keys、list envelopes、status、21 條 path/query；不要為舊 SDD 簡化範例改回 `resource`、`status`、`steps.content` 或 raw conversation array。
- 204 只用於成功 DELETE；其他成功 response 應有契約 JSON。Arrays 必須回 `[]`，nullable response key 必須明確回 `null`。
- `/agent/chat` 與 `/chat` 要共用 auth/quota/idempotency/persistence；`Idempotency-Key` 1..128 且同 principal/body 可 replay。Quota 綁固定 server principal/window，不可按 token 重置。
- Auth role/scope/ownership 只從 Bearer session；不可相信 request `user_id`、新增 role header 或讓 client 選 role。
- Upload 必須驗 MIME + magic bytes + 5 MiB，response/download 不洩漏 filesystem path；content route再次驗 owner。
- Conversation detail 必須回保存當下的 full structured payload、attachments 與 source snapshot。History reopen 不可重新呼叫 Agent、寫 Insight 或扣 quota。
- Teacher 新 chat 只有 `question_count`／實際 `learning_gap`；不可虛構 practice correctness 或動畫結果。Seed authored sample 可有結果，但 `practice_count`、`animation_observation_count` 與 nullable percentages須完整回傳。
- Government route只查 aggregate projection；`daily_aggregates` 是日×區×topic aggregate row，不是 raw event，payload 不得加入 user/profile/conversation/message/upload id 或原文。

## Task 3.2 / UI 接線必須知道

- 啟動/access gate 用 `authApi.createDemoSession()`；user id/role 只取 response session。401 client 會清 token，UI 應回 access gate。切 role 必須交換另一個 server-configured code，不可送 role header。
- 初始 learning/resource route `q`：在使用者動作建立一次 `AgentSubmission`，用 `agentApi.submit()`；navigation 帶 stable `submissionId`，目的頁用 `getSubmission()` 取得同一 completed/in-flight Promise。直接載入 URL 時以 `useRef`/lazy `useState` 建一次 submission。不要在 StrictMode effect 每次生成新 key。
- 傳給 `submit()`／`chat()`／`getSubmission()` 的 `signal` 是 subscriber cancellation：只停止該 component/consumer 等待，共享 transport 仍供其他 consumer 與 navigation 後訂閱者使用。因此 StrictMode effect cleanup 只 abort 自己的 controller，不可呼叫 `cancelSubmission()`，也不可重建 request/key。第一個建立 submission transport 的呼叫決定 shared timeout。
- 只有使用者明確取消整個動作時才呼叫 `agentApi.cancelSubmission(submissionId)`；這會移除 cache 並中止 pending transport。`clearSubmission()` 只做 cache eviction，不會中止 transport。logout、session clear 或 token principal 切換會自動取消 pending action 並清除個人 cache。
- History open 一律呼叫 `conversationsApi.getDetail(conversationId)` 並 render replay payload；不得呼叫 Agent，也不得再用 title regex 判 learning/resource。
- 圖片先 `uploadsApi.uploadImage(file)` 再把 attachment id 放 Agent input；file picker 改成 `.jpg,.jpeg,.png,image/jpeg,image/png`。顯示受保護圖片用 `downloadContent()` 取得 Blob/object URL，不直接把需 Bearer 的 URL當公開圖片。
- Memory 只有按「幫我記住」才 `profileApi.acceptMemory(userId, suggestionId)`；按「不用」只關 UI。成功後重抓/更新 profile；刪除用 `deleteMemory()`。
- Learning render 使用 `learningAnswer.steps[].body/sourceIds` 與 response/source snapshot。只有 `learningAnswer.id !== null` 才可傳給 `ScienceSimulation`；unknown topic 不可 cast 成動畫 key。
- Resource UI 用 `eligibilityStatus` 做 label map；requirements、missing conditions、documents、application window、next step、source note/sources 都來自 view，不再補本機情境事實。
- Teacher 接線必須直接用 server `summary/previousSummary/topics/roster/trend`；正確率顯示 `accuracyPercentage ?? "—"`，動畫率同理，分母使用 `practiceCount`／`animationObservationCount`。不要沿用現在以所有 learning events 當練習分母的推算。
- Government UI 改讀 `eventCount/resourceNeedCount/potentialNeedCount/resourceViewCount` 與 `dailyAggregates`；CSV/modal 只能用這些 aggregate view。Preference/tracking 仍可 localStorage。
- API error/cancel/offline unsupported/provider error 必須顯示為失敗或取消，不能呼叫 `src/data` fixture 冒充成功。`demo:true` 成功回答要顯示離線示範標記。
