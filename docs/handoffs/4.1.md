## 完成內容

### Demo access、session 與授權

- 保留並驗收 server-only `DEMO_ACCESS_CODES`：access code 只映射 DB 中既有且 enabled 的固定 `DemoPrincipal.config_key`；principal 再固定連到 user/role。Request 沒有 `requested_role`、`X-Role`、任意 user id 或無認證後門可改變身份。
- Access code 比對使用 `secrets.compare_digest`，所有 configured code 都會走完比較；重複 code 在 startup 拒絕。成功 token 是 48-byte CSPRNG opaque value，SQLite 只存 SHA-256 hash；Bearer lookup 後再以 constant-time comparison 核對 candidate hash。
- Session TTL 可設定但最多 480 分鐘（8 小時），expiry/revocation/disabled principal 都拒絕；session、quota 與 idempotency 全持久在 SQLite。Auth response 與全部 `/api/v1` response 加 `Cache-Control: no-store`。
- Startup fail closed：沒有 access-code config、config key 不對應 enabled seeded principal、學生沒有 profile、教師沒有 class scope、code 重複／長度錯誤，或 RAG index 缺失、為空、embedding signature 不符時，應用不啟動。`live` 另在設定載入時要求 provider key、chat model、embedding model 與無 credential/query/fragment 的 HTTP(S) base URL。
- 每條業務 API 都保留明確 role dependency：student self/owner、teacher authorized class scope、government aggregate-only。新增整體 role surface 測試確認 role header 無法升權，teacher/government 無法讀 profile、conversation、alert/private upload/resource/Agent 等 student surface；government dashboard 仍只作 SQL aggregate projection，teacher 仍只有名冊與學習摘要。
- `src/api` 無需修改：既有 client 已在任一 authenticated 401 清除 sessionStorage/in-memory token並觸發 session cleanup listeners，會取消/清掉 Agent submission registry。3.2 仍須在 listener/UI auth boundary 清除 TanStack Query 與所有個人/跨角色 page cache，並回 access gate。

### Quota、idempotency 與 attempt safety

- `/agent/chat` 與 `/chat` 仍共用 canonical `agent_chat` operation、同一 principal/day ledger、至少 24 小時 idempotency record 與相同 response snapshot；同 principal + key + canonical body replay 不重扣，不同 body 回 409。
- 每個 quota lease 新增高熵 `attempt_id`。Reservation row 即使在 expiry recovery 後為同 key 重用，conditional finalize/release 也同時核對 row id、attempt id、ledger 與 idempotency identity；舊 attempt 的遲到 finalize 會失敗並 rollback其未提交 message/Insight，遲到 release 為 no-op，兩者都不能碰新 attempt。
- 為既有 pre-4.1 Demo SQLite 增加最小相容 schema upgrade：若 `quota_reservations.attempt_id` 不存在，startup 加欄位並以舊 reservation id 填入既有 row。新 DB 由 metadata 直接建立 non-null 欄位；仍沒有宣稱已建立完整 Alembic migration 系統。
- Concurrent reserve 仍以 SQLite conditional arithmetic update 保證 `used + reserved <= limit`；message、primary Insight、response snapshot、reservation finalize 與 ledger used transition 同 transaction。Provider/error/timeout/cancel-before-commit 先 rollback payload再 release；startup/reserve 只回收真實到期 lease。
- Quota 429 現在同時回 `QUOTA_EXCEEDED`、fresh `details.usage`、`details.retry_after_seconds` 與整數 `Retry-After`（到真實 UTC reset）。重新登入、換 teacher/government 再換回 student，仍讀相同 principal/day ledger。
- Session/suggestion expiry、quota window/reset、idempotency TTL、lease expiry 全用真實 UTC；rate limit 使用 monotonic clock。Offline dataset anchor 只保留給 Demo message/activity/Insight/dashboard 時間。新增測試跨 UTC 午夜建立第二個 ledger，證明 offline mode 不會被 seed anchor 凍結用量視窗。

### Rate、request、CORS、upload 與 provider boundary

- Access exchange 與 Agent 使用獨立 sliding-window buckets：exchange 依直接 client IP；Agent 依 authenticated principal，兩個 chat alias 共用同 bucket。429 `RATE_LIMITED` 皆有 `Retry-After`/`retry_after_seconds`；Agent rate 429 另帶 fresh usage。這是 single-process Demo limiter，不是假裝成 distributed limiter。
- 預設限制：exchange 10/60 秒、Agent 30/60 秒。Rate rejection 不會 reserve quota或呼叫 provider。
- Mutation request body 在 parsing 前受限：JSON/default 64 KiB；唯一 upload route multipart request 6 MiB。Agent message trim 後最多 4000 chars、附件最多 3 個且不重複、opaque path/body/query id 最多 128、Idempotency-Key 1..128；malformed JSON 回 400 統一 envelope，超限 body 回 413。
- Upload 維持單檔 5 MiB、JPEG/PNG declared MIME + magic + Pillow verify/full decode + 40MP 限制。Storage key 隨機；所有 storage path 經 resolved-parent containment，讀取時重驗 size/SHA-256/magic；download 與 Agent 圖片讀取都先驗 authenticated owner，不回 filesystem path。
- CORS 只允許 `FRONTEND_ORIGIN` 列出的 exact HTTP(S) origins（可逗號分隔，禁止 wildcard/path/credential），methods 固定 `GET, POST, PUT, DELETE, OPTIONS`；headers 明列 `Authorization`、`Idempotency-Key`、`Content-Type`、`Accept`、`X-Request-ID`。Response expose `Retry-After`/request id/content metadata。
- Client supplied request id 只接受 1..128 的 `[A-Za-z0-9._-]`；其餘改產生 server id。所有 response 加 `nosniff`、`Referrer-Policy: no-referrer`，API response no-store。
- Runtime mode 仍只由 startup `RUNTIME_MODE` 決定，request 無切換欄位。Provider SDK 仍集中且 `max_retries=0`，request 有 server/provider timeout；provider exception/validation、base URL 與 key 不會進 API error或 health。沒有新增 capability probe、metrics、circuit breaker或外部服務。

## 4.2 必要設定與安全注入

完整三角色 Demo 應在 process/container 啟動環境提供：

- `RUNTIME_MODE=offline_demo` 或 `live`；不能由 request 選擇。
- `DEMO_ACCESS_CODES`：JSON object，完整 Demo 使用已 seed 的 `student_demo`、`teacher_demo`、`government_demo` 三個 key，各值必須不同。值不得放入 repo、`.env.example`、`VITE_*`、image、URL、command line、log或 handoff。
- `APP_DATA_DIR` 及／或 `DATABASE_URL`，以及 `CHROMA_PATH`：4.2 應指向 persistent volume 的明確 absolute paths。
- `FRONTEND_ORIGIN`：exact origin；若本機與部署站都需允許，以逗號列出，不使用 `*`。
- `live` 額外必填 server-only `LLM_API_KEY`、`LLM_MODEL`、`EMBEDDING_MODEL`；`LLM_BASE_URL` 必須是 HTTP(S) URL且不能含 URL credential/query/fragment。4.1 沒有選模型或放入真實 key。

可調但有界的變數與目前 default：

- `AUTH_SESSION_TTL_MINUTES=480`（最大 480）
- `AUTH_EXCHANGE_RATE_LIMIT_REQUESTS=10`
- `AUTH_EXCHANGE_RATE_LIMIT_WINDOW_SECONDS=60`
- `AGENT_RATE_LIMIT_REQUESTS=30`
- `AGENT_RATE_LIMIT_WINDOW_SECONDS=60`
- `MAX_JSON_BODY_BYTES=65536`
- `MAX_MULTIPART_BODY_BYTES=6291456`（不可低到容不下 5 MiB file + multipart overhead）
- `AGENT_DEADLINE_SECONDS=45`
- `AGENT_RESERVATION_TTL_SECONDS=90`
- `IDEMPOTENCY_TTL_HOURS=24`（最少 24）
- `MEMORY_SUGGESTION_TTL_HOURS=24`
- `UNATTACHED_UPLOAD_TTL_HOURS=24`

Access code 應由 CSPRNG 直接產生到 deployment secret store；每個值建議至少 `secrets.token_urlsafe(32)` 的熵級。若 4.2 只能使用外部 env file，應以 `umask 077` 在 repository 外建立、直接把產生器 stdout redirect 到該檔，權限保持 0600，使用 container/runtime secret injection讀入，且不要把值印到 terminal/log或加入版本控制。前端 access gate只 runtime送 code，code 不持久；Bearer token只放 memory/sessionStorage。

4.2 啟動順序必須是：掛載持久路徑與注入 server config → `scripts/seed.py` → 以同一 runtime/embedding config 跑 `scripts/build_index.py` → 啟動 Uvicorn。任一步缺設定、DB principal/scope 未 seed、或 index不 ready都應讓 container/startup失敗，不以空資料或 offline fixture冒充 ready。持久 volume restart smoke需確認 session/quota/idempotency、attempt migration、DB、uploads與 Chroma 都保留。

## 剩餘限制／交接

- Rate limiter 是依 monotonic time的 in-process single-machine Demo機制，restart會清空、不可跨多 Uvicorn workers協調。4.2應維持單 worker；持久 daily quota/idempotency仍由 SQLite提供，不能靠多 worker rate bucket聲稱 distributed安全。
- 沒有實作正式帳號、password、refresh、pepper、rotation/lockout、logout/revoke endpoint或 last-seen batching；這些依使用者指示不是 4.1新增需求。
- 沒有正式 Alembic migration；只有本輪 `attempt_id` 的精確 SQLite相容 upgrade。4.2應以 temporary copy驗舊 DB upgrade與 persistent restart，不把它描述為通用 migration framework。
- Unattached upload cleanup仍在 startup執行；已連結 message的 upload不會被 orphan cleanup刪除。沒有新增 scheduler。
- 真實 provider capability/品質/延遲仍未測，provider/model設定後補；目前只可宣稱 offline Demo與 localhost mock boundary通過。
- 3.2：實作 access gate、角色切換時交換新 server code，token不進 localStorage/URL/log；401除既有 typed client cleanup外必須清全部個人 query/page cache與受保護 image object URLs。每個 Agent UI動作固定一個 idempotency key/submission。
- 5.1：以瀏覽器重驗 access gate、401/cross-role cache、CORS、upload/download、alias/idempotency/quota/rate錯誤呈現與 Docker restart persistence；不要把 skipped live provider當通過。
