## 實作

1. 依 SDD 建立 FastAPI modular monolith、Pydantic schema、SQLAlchemy SQLite、設定與 `requirements.txt`；提供 app factory/lifespan、`/health`、Swagger、統一錯誤 handler 與設定注入接點。配置路徑獨立於 cwd，支援後續 Docker 持久 volume；以虛擬環境安裝，不改系統 Python。
2. 資料模型涵蓋 users/profiles、結構化 memory/suggestion、conversation/messages（完整 structured response/source snapshot）、Insight、alerts/read、policy/curriculum、upload metadata。為 session、固定 principal quota ledger、idempotency/reservation 留最少可靠的 DB 結構；後續 2.2/3.1/4.1 完成服務。不建立無認證業務 route 或相信任意 user_id 的暫用後門。
3. 依固定 wire 契約實作 request/response schemas（含所有 dashboard snapshot）。Mutation 拒絕額外欄位，保留 nullable 與 enum；新聊天的 correctness/animation 是未知，不能以 false/0 補作已知觀察。Schema 要能讓後續服務直接使用，避免兩套定義。
4. `backend/scripts/seed.py` 可重跑不重複，不覆寫使用者後續 profile、memory/read/chat 或 quota。涵蓋 1+ Demo student、10+ policies、3+ alerts、20+ learning events、10+ resource events、5+ conversations。教材覆蓋六理化 topics/真實 source excerpts，政策覆蓋六分類；優先搬移既有作者示範內容並清楚標示 Demo，未知來源 URL/deadline 為 null，不能編造政策仍有效。
5. 教師名冊/授權班級依現有 42 人/3 班語意建立，Demo student 必須可連結到授權名冊。政府資料保留六區六主題，用可追溯的 seeded Insight 聚合，不能只放 UI generator 快照。Seed 相對日期/基準日要有明確策略，日後啟動仍有資料可演示。新 Insight 不得增加虛構作答/動畫結果。
6. 用最少 unique constraints/foreign keys 支援 ownership、單 message 最多一 Insight、read/consent/idempotency 去重、持久原子 quota。Conversation 刪除不誤刪已同意 memory，也不可意外改變歷史統計；相關 FK 決策交接。
7. 只建立 core 基礎，不實作業務 API、LLM/RAG、前端或 Docker。套件 API 若不確定，以官方文件核對。
