## 工作內容

依 `docs/api-alignment.md` 實作後續 Task2/3 可直接使用的 typed API layer。

1. 完整 wire（snake_case）及 view（camelCase）TypeScript interfaces/enums：session/token usage、chat/Agent structured response、learning/source、resource list/detail、profile/memory、conversations list/detail、alerts、upload、teacher dashboard、政府聚合。與既有 `src/types/index.ts` 舊 export 相容，任何必要新增欄位以明確契約處理。重用穩定的既有 type-only interface 可以，但 API 模組不能 import/執行本機 demo generators 或假回答。
2. 強化 `src/api/client.ts`：base URL 使用 VITE_API_URL，支援 same-origin `/api/v1` 預設供 Docker；合理處理斜線；token 注入與 session state 採1.1契約，絕不內建秘密/VITE token。JSON與FormData分開（multipart不可手動設定Content-Type）；使用 `Headers` 正確合併、error envelope、validation fallback、network/abort、timeout、204/empty response，保留 status/code/message 和 Retry-After/usage 等契約欄位。不要新增 Axios 或不需要的依賴。
3. 各業務提供簡潔 typed functions 或物件：Agent `/agent/chat` 為主要入口、`/chat` 相容方法（如果契約需要）；profile update 與明確確認 memory CRUD；history；resource；alert/read；upload 與受認證內容讀取（若契約需要）；dashboard filters；session與usage。URL path/query需 encode，不能把user_id當認證來源。
4. Adapter 必須真的轉換 wire 到現有UI可用欄位，不能只 `as` 假裝相容或用泛用 recursive casing 破壞 dictionary/key values。保留學習 steps/body/sourceIds、教材來源、scenario/practice/follow-up 等豐富欄位，資源 requirements/documents/source/eligibility status，教師既有 filters/summary/topic 使用的形狀，政府只能聚合欄位且不能帶 raw event。
5. 契約若有可選 payload，處理缺省/null而不 crash。限制 optional chaining 掩蓋真實 API 不一致，不用 UI 本機假資料回退而把 API 失敗偽装成功。對學習 topic 等未知值給可明確處理的型別，不能强轉成既有動畫 key 後 crash。
6. 若發現1.1契約有重大歧義或無法在本責任範圍實現，記入 handoff 並向協調者明確報告，不自行更改 contract 或 SDD。不要求使用者确认 routine choice。
