## 實作

1. `POST /api/v1/agent/chat` 與 `/api/v1/chat` alias 共用同一 service、auth、idempotency/quota/persistence。執行 mode/intent → profile → retrieval → eligibility/context → structured generation → primary Insight → persistence。明確 learning/resource 不多打一個 intent LLM call。
2. 集中 `llm/client.py` 提供 generate/embed，使用 server env 的 OpenAI-compatible base/model/key，查官方文件確認實際 SDK/API；使用 OpenAI Docs 技能時告知。模型可設定，不把 CLI 的模型名誤當 app provider 要求。來源、user input/附件都當不可信內容，不允許模型覆寫授權或執行指令。
3. Chroma 本機持久索引兩 corpus，Top K=5，chunk metadata/source id 可追溯；index 可重跑/upsert，不重複。Live 走 embedding API；offline 明確使用可重現的本機示範檢索，文件如實說明與 live 差別，不下載不必要的大模型。
4. Live structured output 必須通過 Pydantic 與引用/source id、practice answer_index、不相容 payload 等 invariant 驗證。政策規則與來源以檢索內容為準，缺條件回 possibly_eligible/needs_confirmation。記憶只發 persisted suggestion，不自動存家庭資料。
5. Offline 只支援既有六學習/六資源及其既有追問情境，搬用 server seed 保留 rich 教學/來源/練習內容，`demo:true`；未知問題回 503，不把隨便題目硬套範本。Live failure 回 502/504，不能降級成假成功。圖片確實由 live multimodal 處理；offline 若無辨識能力要明示，不能聲稱已看懂圖片。
6. 持久保存 user/assistant message、sources、完整 payload、suggestion，最多一個 primary Insight。固定 principal/window 原子 reservation/finalize/refund 與至少24小時 idempotency 須納入 pipeline，4.1 接續加固；同 key 同 body 重試返回原回答，同 key 不同 body 409，alias 不能绕過。成功 commit 与 usage/Insight 一致；失敗不錯扣，重啟不永久占用失敗 reservation。
7. Conversation/attachment ownership、mode 相容、trim長度/附件數與45秒server deadline按契約。新 learning chat 不虛構 correctness/animation；新 Insight 可在下一個 dashboard GET 看見，未知 region 不塞任意區。

2.1 的固定 Demo dataset anchor 只供示範學習/Insight/dashboard 資料時間；session/suggestion 到期、quota 日視窗/reset_at、idempotency TTL 一律真實 UTC，rate limit/timeout 採真實時間或 monotonic clock。不可因離線示範把安全或使用次數的計時凍結。
