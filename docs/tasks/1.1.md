2. 明確列出 SDD/實作衝突及最小影響方案：wire snake_case → TypeScript camelCase adapter；保留既有 source modal、理化教學 steps/body/sourceIds、scenario/practice/follow-up/animation、六資源類別、教師/政府分頁。展示樣式/靜態動畫與科目標籤可留前端，真實回答/來源/學生資料/統計需 API。前端現有 localStorage 偏好、複習安排、政府追蹤清單可保留並註明僅本機；不能假裝後端已儲存。
3. REST `/api/v1` endpoint 表，完整 request/response 欄位、enum、nullable/optional、HTTP status、filter/query、ownership；以 TypeScript wire schema 或等價精確格式寫出，勿只給一句概述。
4. Agent 的主要入口是 `POST /api/v1/agent/chat`，`POST /api/v1/chat` 只能同 service 相容 alias。保持 SDD 模組化單體。不用前端直接呼叫供應商。request 包含 user_id、conversation_id、mode、message、attachment_ids；只加入 UI 真正需要的 category/topic 等選項。定義完整結構化學習回答/資源推薦/來源/記憶建議、conversation/detail 重播訊息與來源資料，含明確 `demo` 或相當欄位標示離線模式。
5. Profile GET/PUT、Memory 明確同意 POST/DELETE、history list/detail/delete、resource list/detail、alert list/read、upload JPEG/PNG、teacher/government dashboard。上傳回應要有 attachment_id、受認證內容下載路徑/URL（若UI需要）與所屬使用者；不可讓前端猜伺服器檔案路徑。過濾/搜尋可基於有限 Demo 全清單在前端處理，避免不必要 API。
6. 現有 dashboard data 很豐富：教師需要 filters、roster/summary/topic/status 的資料以支援所有既有分頁；可 server 回傳完整 snapshot。教師只允許授權的教學資料；不因方便回傳家庭 profile 或原始私人對話。政府只允許 Insight 聚合（日/區域/主題/count/trend），不可回傳個人識別/姓名/家庭/訊息/逐人事件，即使是假資料也別建立這種 endpoint。必要的 SDD KPI 欄位保留，額外 dashboard payload 配合現有實作。明確定義新 Insight 如何改變統計，避免 UI 繼續只讀靜態產生器。
7. 最少 Demo 安全契約：server 配置 token 驗證，登入/存取交換或驗證 endpoint，角色(student/teacher/government)由伺服器決定，user_id 不能讓 request 冒用別人。定義 token/session 生命週期、前端保存策略（不可 VITE 硬編 token）、GET 使用次數/限制（limit/used/remaining/reset 等一致欄位）、429 quota/rate-limit、401/403。不要建立正式帳密系統。明確規定 AI 次數何時保留/扣除、錯誤是否返還、/chat alias 不可規避 quota，且需持久原子處理；Task4實作。
8. 一致 error envelope（包括 validation/upload/timeout/provider/offline 模式）、空清單/204、JSON header vs multipart、cancel/timeout。SDD 現有錯誤 code 盡量保留。
